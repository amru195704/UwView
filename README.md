## ripgrep で探して、klogg で開いている人へ

**その往復を、1回のファイル読み込みにまとめる道具です。**

巨大なログやテキストを調べるとき、多くの人はこうしています——`rg` で探して、当たりを見つけて、
その場所を読むためにビューアで開き直す。**このとき、ファイルは2回読まれています。**

`uvf` は、**探しながら画面に渡す**ところまでを1回の読み込みで終わらせます。

| 51.25GB の1本のファイルで「探して、当たった場所を画面で読む」まで | 時間 |
|---|---:|
| `rg` で探す（55.38秒）＋ klogg で開く（52.55秒） | **107.9秒** ※実測2本の足し算 |
| klogg 単体（開く＋検索） | 108.14秒 |
| **`uvf … -open`** | **53.69秒** |

**約 2.01倍。** 速いアルゴリズムを見つけたからではなく、**読む回数が 2回から 1回になった**からです。
51.25GB ÷ 53.69秒 ＝ 910 MB/s で、この53.69秒の中に**探索・索引構築・画面表示まで**入っています。

> Mac M4／メモリ32GB／外付け USB SSD（素読み 950〜970MB/s）。語は `東京`（94,979件）。
> **毎回 `sudo purge` 後のコールド。** 条件と全データは[実測まとめ](https://uvp.y42u.net/benchmarks/)にあります。

## 1. 探す速さは ripgrep と同等です

`uvf` は索引を作りません。ファイルを順番に1回読んで探します。**ripgrep と同じ土俵**です。

| 検索7種の合計（コールド＋直後の2回目） | ripgrep 15.2.0 | **`uvf`** | 比 |
|---|---:|---:|---:|
| 3GB | **32.30秒** | 33.31秒 | 1/1.03（**ripgrep の勝ち**） |
| 10GB | 158.69秒 | **147.01秒** | 1.08倍 |
| 50GB | 806.22秒 | **735.97秒** | 1.10倍 |

**3GB では負けています。** メモリに載る大きさなので、2回目が完全にキャッシュから返る ripgrep が有利です。
10GB を超えると載らなくなり、`uvf` が 8〜10% 前に出ます。**どちらも律速はディスクの読み出し速度**なので、これは順当な結果です。

**Windows だけは話が違います。**

| Windows ノート・16GB・50GB | ripgrep | **`uvf`** |
|---|---:|---:|
| 検索7種の合計 | 1,780.77秒 | **693.84秒** |

**2.57倍。** これは `uvf` が速いのではなく、**ripgrep の既定のメモリマップ読みが 50GB では裏目に出ている**だけです。
`--no-mmap` を付けると ripgrep は 2.89倍速くなります（[検証記事](https://uvp.y42u.net/blog/uvp-rg-no-mmap-50gb/)）。
`uvf` はメモリマップを使わないので、この落とし穴を踏みません。**Windows で巨大ファイルを `rg` にかけている方は、まず `--no-mmap` を試してください。**

## 2. 開く速さは klogg を少し上回ります（v1.6.6・近日公開）

klogg は優れたビューアです。**開くとき 930 MB/s——媒体の速度を出し切っています。**
v1.6.5 まで、うちは 486 MB/s でその半分でした。**v1.6.6 で、ここを詰めました。**

| ただ開くだけ（コールド） | 3GB | 10GB | 50GB |
|---|---:|---:|---:|
| klogg 24.11.0 | 3.65秒 | 10.98秒 | 52.55秒 |
| UwView 無料版 GUI **v1.6.5** | 5.27秒 | 19.62秒 | 100.6秒 |
| **UwView 無料版 GUI v1.6.6** | **2.99秒** | **10.13秒** | **50.44秒** |
| **対 klogg** | **1.22倍** | **1.08倍** | **1.04倍** |

読み出しは **967／966／969 MB/s**。**3サイズとも同じ値**で、これは媒体の速度そのものです
（3GB はメモリに載る大きさですが 967 止まりなので、キャッシュが効いた値ではありません）。

**大きいほど差は縮みます。** 50GB では 1.04倍——**ほぼ互角**と言うべき差です。
**差がつくのは、開いたあとに「探す」からです。**

## 3. CLI と GUI が、同じファイルを同じエンジンで見ています

ここが `uvf` の本体です。

```bash
uvf japan-latest.osm '東京' -open
```

これで、**探し終えた瞬間に UwView の画面が開き、行番号つきの結果一覧が出ます。**
**画面はもう一度探しません。** CLI が見つけた行の位置・索引の目印・各ヒットの行番号を、そのまま画面へ渡すからです。

| | ファイルを読む回数 | 結果一覧の行番号 |
|---|---|---|
| `rg` → ビューアで開き直す | **2回** | ビューアが索引を作ってから |
| klogg（開く→検索） | **2回** | 索引ができてから |
| **`uvf … -open`** | **1回** | **最初から** |

画面に渡ったあとは、GUI の仕事です。**前後の行を読む・結果一覧からジャンプする・複数キーワードを色分けする・
ブックマークを置く・条件を変えて探し直す。** 調べる作業は、この行き来でできています。

**258.68GB・45億行でも同じでした。** `uvf … -open` が **265.21秒**。
**klogg がこのファイルを開き終わるのに 258秒**かかるので、**klogg が開き終わるのとほぼ同じ時間で、
こちらは探して画面に出すところまで終わっている**ことになります（差 7秒・2.8%）。

> **GUI 単体で開いた場合も同じです。** v1.6.6 から**索引の完成を待たずに検索を始められる**ので、
> 50GB で「開く→探す→画面に出す」の通しが **53.7秒**。`uvf … -open` の 53.69秒と同じところまで来ました。
> **探す語が決まっているなら CLI から、決まっていないなら画面から。どちらでも待ち時間は同じです。**

## 5. 同じファイルに何度も戻るなら — UwView Pro

境界はファイルサイズではなく、**「2問目」**です。

1問目は、klogg も `uvf` も、ファイル全体を1回は読まなければいけません。物理の話なので逃げ場がない。
違うのは**そのあと何が残るか**です。

- **klogg** — 索引は残りません。**開き直すたびに作り直します**
- **`uvf`（無料）** — 索引を作りません。**2問目も1問目と同じ時間**がかかります
- **`uvp`（Pro）** — 1回目に `.uwvz`（元の約1/9・行索引つき）を作り、**2回目以降は元ファイルに触りません**

| 50GB・2問目 | 開く | 検索 | 合計 |
|---|---:|---:|---:|
| klogg | 52.55秒（毎回） | 55.59秒 | 108.14秒 |
| `uvf … -open`（無料） | — | — | 53.69秒 |
| **`uvp`（`.uwvz` あり）** | **0.01〜0.07秒** | **6.34秒** | **6.41秒** |

**klogg の 16.9倍、無料版 `uvf` の 8.4倍。** ここで桁が変わります。

**正直に書くと、1問目は無料の `uvf` が ripgrep と同程度で、`uvp` は `.uwvz`（圧縮＋索引）を作るぶん 15〜20% 遅くなります。**
3GB程度でメモリに収まるファイルなら、2問目以降も ripgrep のほうが速いままです。
**`uvp` が効くのは 10GB を超えて、同じファイルに2回以上聞くとき**です。

`.uwvz` は**元ファイルを消しても検索でき、`-extract` で元に戻せます**。50GB が約 5.7GB になります。
**Edit Upgrade** を足すと、**元ファイルを書き換えずに編集**できます（差分だけを持つ方式なので、保存がファイルサイズに依存しません。48GB で「作業を中断するための保存」が 0秒）。

|---|---|
| 探すだけ・画面は要らない | **`uvf`**（無料）。ripgrep と同等 |

## 主な機能

- **巨大ファイルの閲覧** — 実測最大 **258.68GB・4,509,830,821行**（無料版で到達）。ファイル本体は非常駐
- **`uvf` コマンド** — `-i`（大小無視）・`-E`（正規表現）・`-v`（当てはまらない行）・終了コードは grep 互換（0/1/2）・`-open` で GUI へ
- **検索結果一覧** — ヒット行だけを別ウィンドウに一覧（元の行番号つき）。ダブルクリックで本文へジャンプ・前後の文脈表示・別ファイルへ保存
- **複数キーワードの色分け** — 色覚に配慮した32色・名前付きセット・`.uwvhl` で書き出し・プリセット7種（syslog／HTTP access／JSON／NMEA／GeoJSON／KML ほか）
- **文字コード自動判定** — BOM＋UTF-8 / Shift-JIS / EUC-JP / UTF-16。切替に索引の作り直しは不要
- **リアルタイム Tail** — 他プロセスが書き込み中のログも開けます
- **gzip を直接開く** — `.gz` を展開して開きます
- **マルチタブ・ブックマーク・横スクロール・セッション復元**
- **全OS同一描画** — Avalonia 独自 Skia 描画

**動作環境**: .NET 10 ／ Avalonia UI 12.x ／ Windows・macOS・Linux（＋おまけのブラウザ版）

📄 **機能の詳細・アーキテクチャ・ビルド手順・テストの流し方は、[以前の README（v1.6.5 時点）](2-doc/archive/README-v1.6.5-2026-09.md)にまとめてあります。**
